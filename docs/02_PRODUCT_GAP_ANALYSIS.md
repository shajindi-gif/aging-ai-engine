# 02 — 产品差距分析（对标成熟 AgeTech SaaS）

> 日期：2026-10-19 ｜ 基线：docs/01 审计 ｜ 对标：Honor/Birdie/Wellthy/Papa 等公开功能（详见 docs/03，未逐项核实者标注待核实）

## 三大业务支柱现状 vs 差距

### A. 家庭照护
| 能力 | 现状 | 差距 | 优先级 |
|---|---|---|---|
| 老人档案 | ✅ 有（ElderlyProfile+18 关联模型） | 授权体系刚建立（本轮 P0），无「家属成员邀请/授权撤回」UI，FamilyMember 仅信息记录不含账户绑定 | P2 |
| 家属协作 | ⚠️ 雏形 | 无 CareCircle/ConsentGrant：任何知道档案 ID 的家人无法被正式授权/撤销（本轮已先堵死越权） | P2 |
| 照护任务/提醒 | ✅ SilverCare MVP | 无通知投递渠道（短信未通、邮件未接提醒） | P2 |
| 家属周报/月报 | ⚠️ agent 可生成草稿 | 无导出/发送闭环 | P4 |
| 费用记录 | ⚠️ Order.price 字段 | 无家庭账单视图 | P3 |

### B. 机构 SaaS
| 能力 | 现状 | 差距 | 优先级 |
|---|---|---|---|
| 订单状态机 | ✅ 本轮服务端强制（草稿→确认→进行→完成/取消） | 无争议(Disputed)态与退款联动；无「谁改的」审计字段 | P3 |
| 排班/分配 | ⚠️ caregiverId 字段存在 | 无排班冲突检测、无护理员移动端签到 | P3 |
| 服务记录 | ✅ API 有 | 本轮已加越权防护；缺附件/签名 | P3 |
| 异常事件 | ✅ HealthAlert 三级 | 缺处置工作流闭环 | P3 |
| 运营报表 | ⚠️ dashboard/stats 查库 | 缺收入/工时/服务量维度报表与导出 | P3 |
| 多租户隔离 | ❌ 仅 organizationId 字段 | 无组织成员管理、无租户级权限矩阵 —— 商业化机构版 P0 阻塞项 | P3 |

### C. 政策与知识
| 能力 | 现状 | 差距 | 优先级 |
|---|---|---|---|
| 政策库 | ⚠️ 41 条已核验样本+标注诚实 | 假 sourceUrl 源头待清；无核验日期/失效监控字段 | P4 |
| 补贴匹配 | ✅ 规则引擎公开可用 | 已加「以主管部门审核为准」边界；缺条款引用输出（RAG） | P4 |
| 案例/知识库 | ❌ 框架页（已诚实标注） | 首批 20 案例+来源为 P4 内容工程 | P4 |
| 机构数据库 | ⚠️ 混合示例库（已加横幅） | 需真实公开数据入库流程与认领机制 | P4 |

## 全站体验差距

1. 适老化：仅有 /elder 大字端雏形，无模式切换与语音朗读（任务书 07 章，P2 专项）。
2. 图片体系：全站无真实素材库与授权清单（任务书 05 章，P1 未完成 → docs/10 待建）。
3. 转化链：docs 死链 14 个已修；「免费使用」CTA 已对齐真实公开页；支付仍为人工开通口径。
4. 可靠性：无 CI/监控告警/备份演练记录（P5 发布前必须补最小集）。

## 结论

本轮把「越权读老人健康数据、CRM 泄露、假演示伪装真实、订单状态随意改写」四个会直接伤害客户信任与法律风险的问题修成了可测试闭环；离成熟 SaaS 的最大剩余差距是**家属授权体系（CareCircle/ConsentGrant）、机构多租户管理、真实内容/素材库**三件事，全部列入 docs/12 排期。
